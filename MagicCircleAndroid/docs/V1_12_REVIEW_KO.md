## 검사 방법과 남은 충전 검사

사용자가 S22 화면을 켜고 필요한 경우 직접 잠금 해제한 뒤 앱을 엽니다. 설정의 설치된 접근성 앱에서 Magic Circle Charging을 직접 활성화합니다. 자동 승인, 잠금 우회, 배터리 서비스 모의 조작은 수행하지 않습니다.

1. 실제 갤러리에서 N01 선택 → 미리보기 캡처. 기존 선택값을 변경하기 전에 기록하고 검사 후 복원 여부를 사용자와 맞춥니다.
2. debug 앱 내부 오른쪽 아래 `N01 검토` 버튼으로 검사 화면 진입. 상단 버튼 순서는 언어(KO/JA/EN), 상태(69/100/0/unknown), 강제Canvas, 크기(864×1536/1600×2560/2560×1600), 글자(1×/2×)입니다. 모든 합성 상태는 이 Activity 안에서만 사용하며 서비스나 저장 선택값을 바꾸지 않습니다.
3. 원본 이미지와 864×1536 실제 렌더를 나란히 비교합니다. 제목의 실제 한글 폰트, 선 접점·팔망성·궤도·코어·룬48/54개·반대 회전·청백/금빛·네 은하의 질감과 밀도를 확대 점검합니다. 이 단계 전에는 원본과 동급이라는 결론을 내리지 않습니다.
4. AGSL 기본 경로와 강제Canvas를 각각 캡처합니다. 기본 경로가 선택되었다는 사실만으로 shader 성공을 단정하지 말고 실제 화면과 오류 로그를 함께 확인합니다. 태블릿 크기 버튼은 S22 내부 뷰포트 검사이며 실제 태블릿 하드웨어 검사가 아닙니다.
5. 사용자와 실제 케이블10회 재연결·화면 꺼짐/켜짐·도중 분리를 수행하고 `MagicCircleCharging`의 run별 attach/dismiss를 대조합니다. 모의 전원 이벤트를 실제 케이블 결과로 대신하지 않습니다.

검사 명령(기기1개만 연결, 읽기 전용):

```powershell
./selftest/sanctuary-device-check.ps1
```

현재 프로세스의 crash buffer, gfxinfo, meminfo만 수집합니다. 기기 다중 연결·버전 불일치·앱 crash·프레임 통계 부재는 실패로 알립니다. 로그 전체와 개인 기기 ID는 커밋하지 않습니다. 앱이 실제로 그려지는 동안 실행해야 성능 수치가 의미 있습니다.

## 알려진 별도 검사 실패

기존 `selftest/magic-circle-design.ps1:11`은 `lengthAdjust="spacing"`을 기대하지만 실제 `app/src/main/assets/magic_circle.html:132`는 `spacingAndGlyphs`입니다. 테스트는 HTML 안에 고정 일본어 룬 문구도 기대하지만 현재 문구는158행에서 언어별로 주입됩니다. 두 파일 모두 이번 기준 커밋 `ebae76d` 이후 변경 없음입니다. 기존 테스트의 전제가 현재 다국어 구현과 맞지 않는 것으로 보이지만, 이 작업에서 기대값을 느슨하게 하거나 예전 화면을 수정하지 않았습니다. 따라서 **전체 보조 검사까지 모두 통과했다고 주장하지 않습니다**.

개인 캡처·원본·APK·전체 로그는 로컬 `evidence/v112/`에만 보존하고 Git에서 제외합니다. 더 자세한 명령/결과는 저장소의 `.superpowers/sdd/2026-09-21-stellar-sanctuary-ko/task-5-report.md`에 있습니다.

## GitHub CI 디버그 APK

공개 저장소 `isk01183/YJ_HTML`의 `codex/stellar-sanctuary-v112` 브랜치에서 Android/워크플로 변경을 push하면 표준 Ubuntu runner가 JDK17·Android37로 단위 검사, lint, debug 빌드를 실행합니다. 기본 브랜치 `main`에는 이 workflow가 없으므로 현재 수동 실행은 불가능하며 브랜치 push가 실행 경로입니다. 성공한 경우에만 해당 소스 커밋/실행에 고유한 태그의 **GitHub prerelease 다운로드 자산**으로 APK와 SHA-256 텍스트를 게시합니다. Actions의 artifact 탭에 업로드하지 않고 캐시·빌드 스캔·의존성 제출도 사용하지 않습니다. 첫 원격 실행 `35557392183`은 준비 action 뒤 `sdkmanager`를 찾지 못해 빌드 전 exit127로 실패했으며 APK/Release가 생성되지 않았습니다. runner의 공식 SDK 절대 경로와 설치된 `platforms;android-37.0`을 검증하도록 수정했지만 재실행 결과는 아직 **대기 중**입니다. 성공한 실행/릴리스 링크·원격 APK SHA-256은 재실행 후 기록해야 하며, 실패하거나 저장소가 비공개로 바뀌면 성공으로 취급하지 않습니다.

CI APK는 runner의 임시 debug 서명으로 생성되어 위 로컬 APK(SHA-256 `ce3e9e7bd248909e0efc36944a3cbf10392aa9d3c9c5ecec311e38442c714cb9`)와 다른 바이너리입니다. 기존 설치 앱의 업데이트 호환성을 보장하지 않으며, 로컬 서명키를 GitHub에 업로드하거나 기존 앱 삭제를 요구하지 않습니다. 배포 전에 기기에서 실제 설치 가능성, 원격 APK 서명·버전·SHA-256, code15가 기존 배포 최댓값보다 높은지를 다시 확인합니다. 실제 충전 오버레이/재연결/API23/태블릿/원본 대비 품질 검사는 위의 미검증 상태 그대로입니다.

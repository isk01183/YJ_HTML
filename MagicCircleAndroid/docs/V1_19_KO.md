# v1.19 — 두 VRM 캐릭터와 라이브 배경화면

버전 1.19 / versionCode 22. minSdk 23 유지. 개인 모델을 포함하지 않는 테스트 배포다.

## 사용 방법

첫 화면 → **배경화면 / 잠금화면** → **VRM 캐릭터 · 배경화면** → **VRM 불러오기**.
두 파일을 각각 가져온 뒤 **캐릭터 선택**에서 전환한다. 같은 `test.vrm` 이름이어도 짧은 ID·VRM 형식으로 구분된다.
**위치·크기**에서 가로/세로 ±35%, 크기 50–150%, 눈 깜박임을 모델별로 저장한다.
**배경화면 적용**은 Android 시스템 미리보기를 열며, 시스템에서 홈/잠금 적용을 확정해야 한다. 설정 변경은 다시 적용해야 반영된다.

## 구현

- `VrmModelStore.kt`, `VrmPlacement.kt`: VRM 0.x/1.0 검증, SHA-256별 독립 보관, AtomicFile 목록, 구버전 단일 모델 이전. 개인 파일은 noBackupFilesDir에 저장한다.
- `VrmWebView.kt`, `vrm-viewer/`: 기존 three-vrm/MToon 오프라인 렌더러 공유. VRM0 정면·팔 좌표 보정, 전신/얼굴/자세/깜박임, 화면 비율 기반 위치 조절. 새 엔진이나 유료 API 없음.
- `VrmWallpaperStore.kt`, `VrmWallpaperService.kt`, `VrmRenderHealth.kt`: 홈/잠금/미리보기용 3슬롯, 불변 적용본, 엔진별 WebView/Presentation/VirtualDisplay. 숨김 정지, 렌더러 종료/컨텍스트 손실 복구, 제한된 재시도.
- `VrmPreviewActivity.kt`, `CharacterActivity.kt`, `MainActivity.java`, gallery 자산: 불러오기/선택/이름/설정/시스템 적용. 0프레임 준비 상태에서는 적용 금지, 저장 실패 시 미리보기 설정도 복구.
- 기존 충전 감지 및 마법진 Canvas 코드는 변경하지 않았다. 기존 사용자 Gradle·Kotlin 드로잉 변경은 별도 보존했다.

### 성능 표본 — API 36 로컬 x86_64 에뮬레이터

| 모델/기기 | 5분 앱 PSS | WebView renderer PSS 표본 | 관측 렌더 속도 |
|---|---:|---:|---:|
| VRM0 / 1440×3120 phone | 최대 약 93.4 MiB, 안정 약 89.4–90.6 MiB; 전환 후 약 81.3–81.6 MiB | 약 260 MiB | 약 7–15 fps |
| VRM1 / 2560×1600 tablet | 최대 약 92.5 MiB, 안정 약 88.8–89.6 MiB; 전환 후 약 81.1–81.6 MiB | 약 188 MiB | 약 8–15 fps |

30fps는 **상한**이지 달성 보장이 아니다. 두 에뮬레이터 동시 실행/소프트웨어 GPU 환경의 표본이며 실기기 속도를 추정하지 않는다.
표의 최대값은 주기적 샘플 최대값이며 순간 최대나 GPU 메모리를 뜻하지 않는다. 앱+renderer 외 시스템/GPU 비용은 별도다.
5분 및 전환 시험에서 OOM·반복 실패·단조로운 메모리 누적은 관찰되지 않았다. 장시간 누수 부재를 증명하는 검사는 아니다.
태블릿 첫 MToon 셰이더 준비 중 JS가 테스트의 기존 5/8초 대기를 초과했다. 검사 대기만 실제 로딩 한도에 맞췄으며 원본 텍스처/모델 품질이나 제품 타임아웃은 낮추거나 완화하지 않았다.

## 배포·개인정보

- 원본 2개의 SHA-256은 작업 전과 동일하다. Git/APK/공개 CI에는 개인 VRM 및 모델 화면을 넣지 않는다.
- 공개 APK는 각 사용자가 직접 VRM을 가져온다. INTERNET 권한이 없으며 별도 종량제 비용 경로를 추가하지 않았다.
- 로컬 업데이트 APK는 v1.18과 동일한 디버그 인증서로 서명한다. CI APK의 서명은 다를 수 있으므로 기존 앱에는 `local-update.apk`를 사용한다.
- 얼굴/머리/의상 편집, 춤·걷기, 여러 캐릭터 동시 표시, VRM 충전 오버레이는 이번 버전 범위가 아니다.

# 캐릭터 커스터마이징·배경화면 설계

상태: **2026-10-08 사용자 승인 / 실행 계획 검토 단계**. 문서와 2.5D 우선·실제 3D 후속 분리안을 제시한 뒤 사용자가 “진행해”로 승인했다. 제품 코드는 아직 변경하지 않았다.

## 1. 목표와 현재 확인한 사실

사용자가 외형·체형·의상·색상을 직접 바꾼 캐릭터를 저장하고, 자신이 만든 움직이는 배경화면에 배치한다. 참고 화면의 붉은 단발, 큰 눈, 부드러운 셀 음영과 판타지 튜닉 같은 분위기를 살리되 게임 자산을 추출하거나 재배포하지 않는다. 기본 모드는 2.5D, 최종 목표에는 실제 3D도 포함한다.

- 작업 폴더: `stellar-sanctuary-v112/MagicCircleAndroid`.
- 브랜치: `codex/stellar-sanctuary-v112`, 조사 기준 커밋 `452aa9c`, 앱 v1.16 / versionCode 19.
- Kotlin/Java 네이티브 화면, Canvas 렌더러, HTML 목록 화면이 함께 있다. minSdk 23, targetSdk 37, Java 17을 유지한다.
- `ScreenScene`과 `LayeredSceneRenderer`는 현재 JPG/PNG/GIF 레이어를 합성한다. 일반 이미지 8개 / GIF 2개 제한이 있다.
- `WallpaperArtwork`가 정적·라이브 배경화면 합성을 공유하며, `UploadedWallpaperStore`가 적용 시점의 독립 복사본을 보존한다.
- 저장소 조사에서 캐릭터 부품 그림, 리깅 모델, GLB/GLTF/VRM/FBX/OBJ/BLEND 및 3D 엔진 의존성을 찾지 못했다. 기존 시안은 완성형 캐릭터 자산이 아니다.
- 기존 미커밋 Android Studio/Gradle/개인 드로잉 변경은 보존한다. main 병합, 종량제 API, 유료 자산 구매, 클라우드 기기 테스트는 하지 않는다.

## 2. 구현 방식과 검토가 필요한 범위

| 방식 | 실제 가능한 결과 | 판단 |
|---|---|---|
| 직접 제작한 2.5D 부품과 Canvas 변형을 먼저 구현 | 외형 교체, 체형 변형, 색상 편집, 눈 깜박임·호흡·손 흔들기, 기존 배경화면 연결 | **첫 배포 추천안** |
| 리깅된 3D 자산과 실제 3D 렌더러까지 동시 제작 | 자유로운 시점 회전과 깊이, 메시 변형, 부위별 장비 교체 | 최종 요구에 포함하되 자산 제작과 별도 렌더링 검증 필요 |
| 시안 이미지 한 장의 확대·회전 | 고정된 그림 표시만 가능 | 요구를 충족하지 못하므로 제외 |

**승인된 분리:** 첫 배포에서는 작동하는 2.5D를 완성하고, 실제 3D는 후속 단계로 분리한다. 이는 사용자 요구에서 3D를 삭제한다는 뜻이 아니다. 첫 배포에서 3D 선택은 `준비 중 — 실제 3D 모델 필요`로 표시하고 가짜 3D로 전환하지 않는다.

아래 상세 계약은 이 2.5D 첫 배포안에 해당한다. 3D 모델·리깅·재질 제작과 자유 회전 렌더러는 별도 설계 및 검증이 필요하다.

## 3. 첫 배포에서 실제로 제공할 화면

### 홈 → 캐릭터 관리 → 꾸미기

기존 세 가지 메뉴를 유지하고 `캐릭터 만들기`를 추가한다. 관리 화면에서 생성·편집·복제·이름 변경·삭제·배경화면에 사용을 제공한다. 저장하지 않은 변경은 초안으로 복구하며, 삭제는 확인 후 수행한다.

꾸미기는 `외형 / 체형 / 의상 / 색상 / 동작` 탭으로 구성한다. 휴대전화는 위쪽 미리보기와 아래쪽 스크롤 조절부, 태블릿은 좌우 배치다. 밝은 아이보리·금색 테두리·청회색 선택 표시를 시안에 맞춘다. 조작 영역은 최소 48dp, 글자 확대와 한국어/일본어/영어를 지원한다.

### 외형과 부품 제작

- 성별/몸체 프리셋 2종. 선택을 바꿔도 색상과 장비 선택을 임의로 초기화하지 않는다.
- 초기 제작 범위: 헤어 3종(붉은 단발을 기본으로 하는 단발/긴 머리/묶은 머리), 얼굴형 3종, 눈 3종, 눈썹 3종, 코 3종, 입 3종.
- 부위 선택은 서로 다른 윤곽과 부품을 실제로 교체한다. 입의 기본 형태와 표정·눈 깜박임은 별개의 상태다.
- 얼굴, 앞머리/뒷머리, 몸통, 상완/전완, 허벅지/종아리, 손/발을 분리 제작한다. 부품에는 접점, 겹침 여유, 색상 영역, 관절 기준점을 둔다.
- 그리기 데이터는 원본 벡터 경로와 채색 영역으로 관리한다. 확대된 단일 시안이나 목업 UI를 캐릭터 자산으로 사용하지 않는다.
- 초기에 기본 전신·얼굴 확대·옆모습 느낌의 제한된 기울기 캡처를 시안과 비교한다. 단순 도형 인형이나 낮은 품질의 임시 그림을 시안 수준 완성으로 보고하지 않는다.

### 체형

모든 항목은 슬라이더와 숫자 입력을 함께 제공한다. 아래 범위는 승인된 첫 배포 범위다.

| 항목 | 기본값 | 조절 범위 |
|---|---:|---:|
| 키 | 160cm | 120–200cm |
| 머리 크기 | 100% | 80–120% |
| 어깨너비 | 100% | 80–120% |
| 상체 길이 | 100% | 80–120% |
| 팔 길이 | 100% | 80–120% |
| 다리 길이 | 100% | 80–120% |
| 몸통 두께 | 100% | 70–130% |
| 팔 두께 | 100% | 70–130% |
| 다리 두께 | 100% | 70–130% |

키는 발바닥부터 정수리 기준점까지의 캐릭터 내부 수치이며 휴대전화 화면의 물리적 cm를 뜻하지 않는다. 머리카락·헤일로·날개는 키 계산에서 제외한다. 비율을 바꾸면 부분 간 상대 비율을 먼저 계산하고 전체 높이를 선택한 키에 맞춘다. 따라서 다리 길이를 바꿔도 키 숫자가 몰래 바뀌지 않는다. 키 변경은 항상 현재 각 비율값을 유지한다. 시안의 `전체 크기 비례 유지`는 동작이 모호한 켜기/끄기 대신 이 규칙을 설명하는 안내로 표시한다.

미리보기 확대/축소와 체형 변경을 구분한다. 핀치는 보기 배율만 바꾸고 체형은 명시적 조절부로만 변경한다. 키를 조절하는 동안 발밑 기준선과 보기 배율을 고정한다. `화면에 맞춤`, `보기 초기화`, `체형 초기화`는 서로 분리한다. 목·팔꿈치·무릎·손목 접점이 벌어지지 않도록 동일 관절 좌표를 몸체와 의상이 공유한다.

### 의상과 색상

- 여섯 독립 슬롯: **헤일로 / 머리장식 / 몸통 / 장갑 / 신발 / 날개**. 헤어스타일은 머리장식과 별도다.
- 초기 선택: 헤일로 2종+없음, 머리장식 2종+없음, 몸통 3종, 장갑 2종+없음, 신발 2종, 날개 2종+없음. 기본 몸통·신발은 항상 남겨 편집 중 의도하지 않은 나체가 나타나지 않게 한다.
- 의상은 체형 변형과 같은 관절을 사용한다. 헤일로는 머리, 날개는 등, 장갑은 손목, 신발은 발 기준점에 부착한다. 장비를 끄거나 바꿔도 다른 슬롯의 선택과 색상을 바꾸지 않는다.
- 피부·머리카락·눈·각 장비의 기본색/보조색을 독립 편집한다. RGB 각 0–255와 HEX `#RRGGBB`를 서로 동기화한다. 예: `80,150,220` ↔ `#5096DC`.
- 숫자/HEX 입력 도중의 빈칸·부분 입력은 허용하되 마지막 유효색을 유지한다. 잘못된 값은 오류를 표시하고 저장하지 않는다. 색을 변경해도 음영과 선화는 남긴다.
- 색상 대화상자의 취소는 이전 색으로 복원한다. 부위별 기본색 복원과 캐릭터 전체 초기화를 구분한다.

### 동작과 배경화면 연결

초기 동작은 `가만히 / 호흡·눈 깜박임 / 손 흔들기`다. 의상도 관절과 함께 움직인다. 2.5D는 층별 겹침·음영·제한된 흔들림을 제공하며, 평면 회전을 자유로운 3D 시점 회전이라고 표시하지 않는다.

`배경화면에 사용`은 기존 화면 편집기에 캐릭터를 **하나의 전용 캐릭터 레이어**로 추가한다. 캐릭터의 내부 수십 개 부품을 일반 이미지 8개 제한에 낱개로 넣지 않는다. 첫 배포는 작품당 캐릭터 1개, 기존 이미지 최대 8개/GIF 최대 2개를 유지한다.

배치 편집은 위치·크기·각도·좌우 반전·숨김·앞뒤 순서를 제공한다. 저장 캐릭터를 편집해도 이미 만든 작품이나 적용된 배경화면은 조용히 바뀌지 않는다. 작품에는 캐릭터 설정의 독립 복사본을 넣고, 사용자가 `캐릭터 새 설정 가져오기`를 선택할 때만 갱신한다.

홈/잠금 및 정적/라이브 배경화면은 기존 적용 흐름을 재사용한다. 시스템 미리보기·확인 없이 사용자의 배경화면을 바꾸지 않는다. 배경화면 동작은 충전 애니메이션의 1/3/5/7초 제한을 받지 않는다. 첫 배포의 캐릭터는 배경화면용이며, 충전 캐릭터 연결은 별도 후속 요청으로 남긴다. 기존 충전화면과 재연결 감지는 그대로 보존한다.

## 4. 최소 변경 구조와 저장 안전성

- 새 캐릭터 설정/검증과 로컬 보관함: 외형·비율·색상·장비·동작을 명시적인 ID/수치로 저장한다. ID 허용 목록, 유한한 수치, 범위, 이름 길이 1–40자를 검증한다. 외부 URI나 실행 스크립트를 받지 않는다.
- 새 전용 캐릭터 렌더러: 편집 미리보기, 썸네일, 배경화면이 같은 계산과 부품을 사용한다. 원본 설정은 불변 스냅샷이며 렌더러 간 가변 Paint/Path를 공유하지 않는다.
- 새 관리/편집 Activity: 기존 MainActivity의 검증된 내부 이동 방식으로 진입한다. 외부 앱에 편집 Activity를 노출하지 않는다.
- 기존 `ScreenScene`에는 이미지 레이어와 별개인 선택적 캐릭터 레이어를 더한다. 미지정인 기존 작품은 완전히 같은 방식으로 읽고 그린다. 일반 이미지 가져오기는 캐릭터 데이터와 섞지 않는다.
- `LayeredSceneRenderer`, `ScreenEditorView`/`Activity`, `WallpaperArtwork`, `UploadedWallpaperStore`에서 캐릭터 레이어를 연결한다. 적용 시점에 설정과 부품 버전을 보존해 라이브 배경화면이 후속 편집·삭제의 영향을 받지 않게 한다.
- 캐릭터 보관함은 별도 원자적 파일과 복구 사본으로 저장한다. 기존 미디어 manifest 확장 시 이전 정상 파일을 보존한 후 검증된 새 파일로 교체한다. 손상된 파일을 빈 데이터로 덮어쓰지 않는다.
- 비정상 종료/회전 시 초안을 복구한다. 저장 실패 시 이전 저장본은 유지하고 오류를 보여준다. 캐릭터 삭제가 기존 작품·적용 스냅샷이나 원본 이미지 파일을 삭제하지 않는다.
- 기존 일반 이미지·충전 정보·선택 목록·비활성 상태·언어·지속시간 설정에 대한 이전 버전 복원 테스트를 유지한다.

## 5. 품질·성능·완료 기준

1. 기본 외형을 승인된 시안과 나란히 캡처한다. 큰 눈/짧고 둥근 얼굴/붉은 단발/파란 튜닉의 비율·색·선화·음영을 비교한다. 기능 성공만으로 시안 품질 일치를 주장하지 않는다.
2. 모든 외형 부품과 의상 슬롯이 독립 변경되며 RGB/HEX가 정확히 왕복한다. 입력 중 오류·취소·초기화도 확인한다.
3. 체형 최소/기본/최대와 경계 조합에서 접점, 옷 겹침, 신발과 바닥, 부착 위치를 확인한다. 숫자·슬라이더·실제 그림이 같은 값을 반영해야 한다.
4. 저장/재실행/회전/초안 복원/복제/삭제/저장 공간 부족을 검증한다. 기존 v1.16 데이터는 그대로 열려야 한다.
5. 배경화면 미리보기·정적 출력·라이브 출력의 첫 프레임이 같은 구성을 사용한다. 적용 취소, 보관함 편집·삭제 후에도 이미 적용한 화면을 보호한다.
6. 그리기 객체와 부품 경로를 캐시하고 변경된 부품만 재계산한다. 애니메이션은 최대 30fps부터 측정하며 보이지 않는 화면에서는 프레임 요청을 중지한다. 과도한 소프트웨어 블러, 프레임별 이미지 디코딩, 전체 비트맵 재생성을 피한다.
7. `testDebugUnitTest`, `lintDebug`, `assembleDebug`와 관련 계측 테스트를 통과시킨다. API 36 휴대전화/태블릿 에뮬레이터에서 실행 화면과 오류 로그를 확인한다. 삼성 실기기 미확인 항목은 별도 표시한다.
8. 실제 첫 배포는 v1.17 / versionCode 20을 제안하되 배포 직전 최신 버전을 다시 확인한다. 호환 서명, APK 해시, GitHub Actions 결과와 휴대폰용 공개 직접 다운로드 링크를 제공한다. 이번 설계 문서 단계에서는 버전을 올리거나 새 APK를 배포하지 않는다.

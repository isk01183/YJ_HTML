# v1.20 — VRM 캐릭터와 이미지로 만드는 배경화면

작성일: 2026-10-08 · 기준 커밋: `79545be` (v1.19)
상태: 사용자가 승인한 기능 구성을 구체화한 설계. 문서 검토 대기이며 제품 구현·APK 배포 완료 문서가 아니다.

## 1. 목표와 승인 범위

사용자가 v1.19에서 가져오고 배경화면에 적용한 두 VRM 캐릭터를 기존 배경화면 만들기 화면에서도 목록으로 선택한다. 선택한 실제 3D 캐릭터와 업로드 이미지를 한 작품으로 배치하고 저장·재편집·라이브 배경화면 적용까지 연결한다.

- 한 작품에는 캐릭터 1명과 이미지 최대 8개를 배치한다. 이미지 중 GIF는 기존 제한인 최대 2개를 유지한다.
- 캐릭터 위치·크기·표시 여부·이미지와의 앞뒤 순서·눈 깜박임을 조절한다. 캐릭터를 사진이나 영상으로 대체하지 않는다.
- 이미지의 이동·확대·회전·좌우 반전·표시 여부 편집은 기존 기능을 유지한다.
- 기존 2.5D 캐릭터 작품, 이미지 작품, VRM 단독 배경화면, 충전 애니메이션을 보존한다.
- 개인 모델·이미지는 기기 내부에서 처리한다. 추가 유료 서비스·서버·3D 엔진·INTERNET 권한을 추가하지 않는다.

이번 범위에는 여러 VRM 동시 배치, 캐릭터 외형·의상 편집, 새 동작 제작, VRM 충전 애니메이션 연결을 포함하지 않는다. VRM 조합 작품은 라이브 적용으로 제공하며 정지 이미지 내보내기는 추가하지 않는다. 기존 작품의 정지/라이브 선택은 유지한다.

## 2. 화면 흐름

1. 첫 화면의 기존 **배경화면 만들기**로 들어간다.
2. **캐릭터 선택**에서 등록한 VRM 목록을 연다. 이름·VRM 버전·짧은 식별자로 같은 파일명의 두 캐릭터를 구별한다. 기존 2.5D 목록도 별도 구분하여 유지한다.
3. VRM이 없으면 기존 가져오기 화면으로 안내한다. 돌아온 뒤 목록을 갱신하며 작성 중인 작품은 유지한다.
4. 선택한 캐릭터와 JPG·PNG·GIF를 미리보기에서 함께 표시한다. 캐릭터는 이미지 사이 어느 순서에도 배치할 수 있다.
5. 목록에서 선택한 레이어만 조작한다. 캐릭터는 드래그 이동·두 손가락 크기 조절 및 수치 입력을 제공한다. 이번 VRM은 정면을 유지하며 두 손가락 회전은 이미지 레이어에만 적용한다.
6. 저장하면 기존 작품 목록에 나타나고 다시 열어 수정할 수 있다. 시스템 라이브 배경화면 미리보기에서 사용자가 적용을 확정한다.

한 작품의 캐릭터 슬롯은 2.5D 또는 VRM 중 하나다. 종류를 바꾸면 편집 중 슬롯만 교체하며 원본 보관함과 현재 적용된 배경화면은 바꾸지 않는다. 캐릭터 레이어 제거도 모델 파일 삭제가 아니다. 한국어·일본어·영어를 유지한다.

## 3. 재사용할 구조

현재 편집기는 `ScreenScene`과 `LayeredSceneRenderer`로 이미지 및 2.5D 캐릭터를 그린다. VRM은 `VrmModelStore` 목록과 `VrmWebView`, `VrmWallpaperService`의 별도 렌더 경로를 사용한다.

채택 방식은 **기존 네이티브 이미지 레이어 + 투명 VRM WebView 합성**이다. 이미지 전체를 WebGL로 다시 구현하거나 정지 캡처로 변환하지 않는다. 기존 이미지/GIF 디코딩, VRM 재질·표정, 오프라인 접근 제한을 재사용할 수 있다.

화면의 아래부터 다음 순서로 구성한다.

1. 검은 기본 배경 및 캐릭터 뒤쪽 이미지 레이어.
2. 투명 배경의 실제 VRM 렌더 화면.
3. 캐릭터 앞쪽 이미지 레이어.
4. 편집 중일 때만 선택 표시와 조작 UI.

하나의 합성 뷰를 편집기·전체 미리보기·VRM 배경화면 서비스에서 공유한다. 배경화면에서는 기존 `Presentation`/`VirtualDisplay` 경로 안에 이 뷰를 배치한다. 배경화면 홈 터치를 편집 동작으로 가로채지 않는다.

`LayeredSceneRenderer`에 필요한 범위 그리기만 추가한다. 한 합성 화면의 이미지 캐시는 한 소유자가 관리하고 앞/뒤 레이어 때문에 같은 이미지를 두 번 디코딩하지 않는다. 위쪽 레이어는 검은색으로 지우지 않고 투명하게 그린다. 기존 Canvas 단독 호출의 기본 동작은 바꾸지 않는다.

VRM 렌더러는 이미 투명 WebGL 출력을 지원한다. 합성 모드에서만 WebView와 HTML 배경을 투명하게 하고 기존 바닥 원형 장식을 숨긴다. 단독 VRM 화면의 배경은 유지한다. 새 네트워크/파일 URL 허용이나 JavaScript 네이티브 브리지는 필요하지 않다.

## 4. 저장 데이터와 호환성

- `ScreenScene`에 선택적 VRM 레이어를 추가한다. 내용은 검증된 모델 ID, `VrmPlacement`, 표시 여부, 이미지 사이 삽입 위치다. 기존 2.5D 필드와 동시에 설정할 수 없다.
- 이전 작품에서 새 필드가 없으면 VRM 없는 기존 작품으로 읽는다. 기존 작품·임시 저장본을 일괄 재작성하거나 삭제하지 않는다.
- VRM 위치·크기는 기존 `VrmPlacement` 범위(화면 중앙 기준 ±35%, 기본 전신 대비 50–150%)를 재사용한다. 편집기의 화면 좌표 변환을 한 곳에서 처리하여 편집 미리보기와 실제 배경화면이 같은 구도를 사용한다.
- 캐릭터 교체 시 배치 설정을 유지하고 모델 ID만 바꾼다. 모델 목록에서의 단독 미리보기 선택/설정과 작품별 배치는 독립적으로 저장한다.
- 모델이 누락된 작품도 나머지 보관함까지 읽기 실패로 만들지 않는다. 해당 작품에 오류와 모델 재선택을 안내하고 원래 작품 데이터는 보존한다. 누락 상태로 배경화면 적용은 허용하지 않는다.
- 가져온 이미지는 기존 편집 전용 가져오기 경로를 사용한다. 재료 이미지가 일반 선택 목록에 중복 노출되는 예전 문제를 되살리지 않는다.
- 작품 목록의 미리보기는 실제 캐릭터를 빠뜨린 이미지를 정상 결과로 표시하지 않는다. VRM 합성 작품은 명시적인 캐릭터 표시와 작품 이름을 제공하고, 실제 외형은 작품 미리보기에서 확인한다. 목록마다 WebView를 여러 개 실행하지 않는다.

## 5. 적용본과 기존 배경화면 보호

VRM이 있는 작품만 기존 VRM 서비스 슬롯으로 연결한다. VRM 없는 작품은 기존 Canvas 서비스 경로를 그대로 사용한다.

- 적용 시 모델 ID·배치·이미지 변환·겹침 순서를 고정한 불변 적용본을 만든다. 이미지 파일은 기존 미디어 사용 보호 기능을 통해 읽고 앱의 `noBackupFilesDir` 아래 적용본에 복사한다.
- 모델은 삭제 기능이 없는 기존 읽기 전용 보관본을 ID로 참조한다. 이미지 파일 복사와 유효성 검증이 성공한 뒤에만 적용본을 원자적으로 확정한다.
- 기존 v1.19 적용본도 계속 읽는다. 새 적용본 형식에 이미지 정보가 추가되어도 기존 슬롯을 자동 변환하지 않는다.
- 홈·잠금에서 사용 중인 슬롯은 덮어쓰지 않는다. 사용 여부를 확인할 수 없거나 안전한 슬롯이 없으면 안내하고 중단한다.
- 적용 준비부터 시스템 미리보기 종료까지 중복 적용 요청을 막는다. 서로 다른 화면에서 요청해도 준비 중인 슬롯을 재사용하지 않으며 추가 요청은 안내 후 거절한다.
- 작품을 편집·삭제하거나 새 시스템 미리보기를 취소해도 현재 배경화면은 유지된다. 모델 선택만으로도 배경화면은 바뀌지 않는다.
- 이미지/GIF와 VRM의 초기 준비 및 실제 첫 프레임을 확인한 후 적용 단계를 허용한다. 로딩 실패 시 다른 모델이나 정지 배경으로 임의 전환하지 않는다.
- 홈/잠금 적용 대상은 시스템 UI가 제공하는 범위를 따르며, 확인하지 못한 대상을 적용 성공으로 표시하지 않는다.

## 6. 성능과 실패 처리

- 장면당 VRM WebView는 하나만 유지한다. 드래그나 크기 변경 때 모델을 다시 로드하지 않고 설정만 갱신한다.
- 화면이 보이지 않거나 꺼지면 VRM과 GIF의 프레임 갱신을 함께 멈춘다. 이미지는 기존 제한된 메모리 예산과 축소 디코딩을 유지하고 캐릭터 원본 외형을 임의로 낮추지 않는다.
- 닫기·화면 재생성·모델 교체에서 이미지/VRM 자원을 정리하고 오래된 비동기 결과를 버린다. 편집기에서 전체 미리보기 또는 시스템 미리보기로 넘어갈 때 이전 합성 화면을 해제해 불필요한 중복 디코딩을 피한다. 복귀 시 저장한 편집 상태로 복구한다.
- v1.19의 가시 시간 기준 로딩 제한, 최대 2회 오류 재시도, 수동 재시도, 엔진별 세대 검사를 유지한다. 이미지 준비 실패는 명확히 표시하고 불완전한 적용본을 발행하지 않는다.
- 단독 VRM과 이미지가 동시에 실행되므로 기존보다 메모리를 더 쓴다. 30fps나 특정 전력 사용량을 사전 보장하지 않는다. 상한 조합의 메모리/프레임을 측정하고 실패하면 한도를 무작정 풀지 않는다.
- 가상 디스플레이에서 투명 WebView와 Canvas가 실제로 합성되는지는 렌더 시험으로 확인해야 한다. 검증 실패 시 성공으로 보고하거나 몰래 캡처 방식으로 바꾸지 않는다.

## 7. 완료 기준

1. 기존 두 VRM이 편집기 목록에 보이고 각각 선택·교체할 수 있다. 기존 2.5D 작품도 정상이다.
2. VRM + JPG 배경 + 투명 PNG 전경 + GIF를 조합해 순서를 바꾸고, 미리보기와 실제 라이브 배경화면을 비교한다. 숨김/복귀·회전 뒤에도 움직이는 GIF 배경과 PNG 전경이 캐릭터의 올바른 앞뒤에 보여야 한다. 캐릭터 뒤에 불투명 사각형이나 기존 바닥 장식이 남지 않아야 한다.
3. 선택 레이어 고정, 이동·크기 변경, 이미지 회전·반전, 표시 전환, 저장·재편집, 앱 재시작 후 복구를 검사한다.
4. 한도(8개 이미지/2개 GIF), 잘못된 ID·배치, 누락/손상 파일, 저장 공간 부족 및 실패 후 기존 데이터 보존을 자동화 검사한다.
5. 미리보기 취소, 작품 편집·삭제 후 적용본 유지, 홈/잠금 각각 다른 적용본, 이전 v1.19 단독 배경화면 읽기를 검사한다. 적용본 생성 중 프로세스 종료·취소와 중복 적용 요청에서도 이전 적용본은 읽을 수 있고 미완성 복사본이나 같은 슬롯의 충돌이 노출되지 않아야 한다.
6. 전화/태블릿 API 36 에뮬레이터에서 실제 화면, 가로/세로 회전, 숨김/복귀, 렌더 오류 복구, 메모리와 프레임을 확인한다. 연결된 Galaxy 실기기는 승인된 연결이 가능한 경우 추가 검증하며 에뮬레이터 결과로 삼성 정책까지 보장하지 않는다.
7. `testDebugUnitTest`, `lintDebug`, `assembleDebug`, 관련 Android 및 웹 검사를 통과하고 AST-only Graphify를 갱신한다.
8. 배포 시 v1.20 / versionCode 23으로 증가한다(새 배포가 있으면 그보다 높은 번호). 기존 Actions 빌드 성공과 로컬 업데이트용 APK의 버전·서명·공개 다운로드 해시를 확인하고 휴대폰용 직접 링크를 제공한다. 개인 VRM·이미지는 Git/APK/CI artifact에 넣지 않는다.

## 8. 변경 경계와 다음 단계

주요 변경 대상은 `ScreenScene`, `ScreenEditorActivity/View`, `LayeredSceneRenderer`, VRM WebView/웹 뷰어, VRM 배경화면 저장/서비스, 배경화면 적용·작품 목록 연결과 관련 검사다. 재사용 합성 뷰가 필요하면 기능 하나로 분리한다. 새로운 범용 렌더 프레임워크는 만들지 않는다.

충전 감지 로직, 사용자 Kotlin 드로잉 파일, 기존 Gradle/디버그 화면 수정사항은 건드리지 않는다. 기존 작업 브랜치에서 본 작업만 커밋하며 main은 병합하지 않는다.

다음 단계는 **이 설계 문서 검토 → 구현 계획 검토 및 실행 방식 선택 → 구현·검증·APK 배포**다. 이 문서 작성만으로 기능이 구현되었거나 새 다운로드 파일이 제공된 것은 아니다.

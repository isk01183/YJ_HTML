# v1.19 — 두 VRM 캐릭터 보관·선택 및 실시간 배경화면

작성일: 2026-10-08 (한국 시간)
상태: 대화에서 승인한 범위를 구체화한 설계. 이 문서의 사용자 검토 후 구현 계획을 작성한다. 제품 구현·배포 완료 문서가 아니다.

## 1. 목표와 범위

이전 모델과 새 모델을 모두 원래 외형으로 표시하고, 앱에 함께 보관하여 선택한 캐릭터를 실제 3D 라이브 배경화면으로 사용한다. 두 모델을 한 화면에 동시에 표시하는 것은 이번 범위가 아니다.

- 모델 선택, 위치·크기 조절, 눈 깜박임 설정, 시스템 배경화면 적용을 제공한다.
- 기존 마법진·충전 애니메이션·2.5D 캐릭터·업로드 이미지 기능은 변경하지 않는다.
- VRM 원본을 수정하거나 이미지/영상으로 바꾸지 않는다. 원본 외형을 유지하며 최적화는 화면 비교 후 적용한다.
- 개인 VRM은 기기 내부에만 저장한다. 공개 APK·Git·CI artifact에 포함하지 않는다.
- 기존 작업 브랜치를 유지하고 main은 병합하지 않는다. 추가 유료 API, 유료 기기 테스트, 새 3D 엔진을 사용하지 않는다.

## 3. 채택하는 방식

기존 오프라인 three-vrm 3.5.5 / three.js 0.180.0을 재사용한다. 기존 미리보기와 별도 배경화면 서비스가 같은 렌더 코드·파일 접근 정책을 사용한다. 실험에서 확인한 `WebView → Presentation → 앱 전용 VirtualDisplay → WallpaperService Surface` 경로를 정식 생명주기에 맞게 보강한다.

새 네이티브 3D 엔진으로 교체하는 방안은 재질·표정 재현 차이와 의존성 증가 때문에 제외한다. 영상 반복 방안은 실시간 3D와 위치 조절 요구에 맞지 않아 제외한다.

기존 Canvas 마법진 서비스를 VRM용으로 개조하지 않는다. VRM 전용 서비스와 기존 VRM 화면의 연결만 추가하여 충전 감지 및 마법진 렌더링을 보존한다.

## 4. VRM 0.x / 1.0 지원

- 공통 GLB·JSON·buffer/accessor 범위·텍스처 내장 여부 검증을 유지한다.
- 확장 키와 specVersion을 명확히 구별한다. 1.0의 `humanoid.humanBones` 객체와 0.x의 `humanBones` 배열을 각각 검증한다. 중복/잘못된 뼈 인덱스, 손상 파일, 외부 리소스는 거절한다.
- 로더가 두 형식을 지원하더라도 앱의 입력 검증을 생략하지 않는다. 알 수 없는 버전과 양쪽 VRM 확장이 모순되는 파일도 거절한다.
- VRM 0.x는 라이브러리의 `VRMUtils.rotateVRM0`를 한 번만 적용하여 1.0과 같은 정면으로 맞춘다. 두 모델의 전신·얼굴·양팔 자세·눈 깜박임을 각각 확인한다.
- 파일당 64MiB, 개별 텍스처 최대 4096, 내장 이미지 수 64, 기하 데이터 한도를 유지한다. 총 텍스처 상한은 새 모델에 필요한 범위인 **40×1024²픽셀**로 제안한다. 무제한으로 풀지 않는다.
- 이 상한은 실제 메모리·렌더 시험을 통과해야 배포한다. 신규 모델의 비압축 RGBA 이미지 합계만 약 154.25MiB이며 GPU 복사·밉맵·기하 데이터 비용은 별도다. 실패하면 조용히 저화질로 바꾸지 않고 원인을 보고한다.
- `combineSkeletons`와 `removeUnnecessaryVertices`는 기존대로 사용한다. `combineMorphs`는 모바일 모프 메모리를 줄일 수 있으나, 얼굴과 표정이 동일한지 두 모델 비교를 통과한 경우에만 추가한다.

참고: [three-vrm 공식 VRMUtils 문서](https://pixiv.github.io/three-vrm/docs/classes/three-vrm.VRMUtils.html), [공식 두 버전 로딩 예제](https://github.com/pixiv/three-vrm/blob/dev/packages/three-vrm/examples/dnd.html). 설치된 3.5.5 코드에서도 VRM 0.x 로더와 방향 보정 지원을 확인했다.

## 5. 모델 보관과 기존 데이터 이전

- 기존 `VrmModelStore`를 여러 모델을 보관하도록 확장한다. 별도 DB 라이브러리나 서버는 추가하지 않는다.
- 내부 식별자는 파일명의 `test.vrm`이 아니라 검증된 파일 내용의 SHA-256이다. 같은 이름의 두 모델이 서로 덮어써지지 않는다. 같은 내용 재가져오기는 중복 복사하지 않는다.
- 저장 위치는 앱의 `noBackupFilesDir`이며, 가져온 원본은 변경하지 않는다. 임시 파일 검증 → 모델 파일 확정 → 원자적 목록 갱신 순서로 저장한다. 가져오기 취소·실패·저장 공간 부족 시 기존 목록과 모델을 유지한다.
- 목록에는 구분 이름, VRM 형식, 크기를 보여준다. 파일명이 같으면 짧은 ID를 함께 표시하며 사용자가 이름을 변경할 수 있다. 작은 실시간 WebView 여러 개를 썸네일로 띄우지 않는다.
- 현재 v1.18의 단일 `vrm-preview/model.vrm`을 최초 실행 시 목록으로 이전한다. 새 저장본과 목록의 검증 완료 전에는 기존 파일을 건드리지 않으며, 이번 버전에서 기존 파일을 삭제하지 않는다. 재실행해도 중복 이전하지 않는다.
- 미리보기에서 선택한 모델과 시스템 배경화면에 적용된 모델을 분리한다. 목록 선택·가져오기는 배경화면을 변경하지 않는다.
- 이번 범위에서는 모델 파일 삭제 기능을 추가하지 않는다. 기존 모델을 보존하고 두 모델 전환을 우선 완성한다.

## 6. 화면과 설정 흐름

기존 캐릭터 관리 화면의 `VRM 3D 미리보기` 진입점을 확장한다. 첫 화면의 배경화면 영역에서도 같은 VRM 화면에 접근할 수 있게 하되 중복 편집 화면은 만들지 않는다.

1. 파일 선택기로 VRM을 가져오거나 보관된 모델을 선택한다.
2. 선택한 모델의 실제 3D 미리보기를 보여준다. 로딩·실패 상태에서는 적용 버튼을 사용할 수 없다.
3. `배경화면 설정`에서 가로/세로 위치, 크기, 눈 깜박임을 조정한다. 기본값은 중앙·전신·깜박임 켜짐이다. 슬라이더와 값 표시, 초기화 버튼을 제공하고 모델별로 설정을 기억한다.
4. 위치는 화면 중앙 기준 가로/세로 각각 화면 폭/높이의 -35%~+35%로 저장하고 크기는 기본 전신 구도 대비 50–150%로 제한한다. 세로/가로 화면에서 같은 비율로 재계산하며 유한하지 않은 값은 기본값으로 복구한다. 이번 단계는 고정 정면이며 홈 화면 터치를 캐릭터 조작에 가로채지 않는다.
5. 시스템 미리보기로 이동하고 사용자가 시스템의 적용 버튼을 눌러 확정한다. 시스템을 건너뛰어 개인 배경화면을 자동 변경하지 않는다.

한국어·일본어·영어를 유지한다. 머리카락·옷·얼굴 편집, 여러 캐릭터 동시 표시, 춤·걷기 애니메이션, VRM 충전 오버레이는 이번 범위에 포함하지 않는다.

## 7. 적용과 취소의 안전성

- 기존 `UploadedWallpaperStore`의 불변 적용본·빈 서비스 슬롯 패턴을 따른다. VRM 전용 슬롯 3개를 사용하며 이미지 업로드 슬롯과 섞지 않는다.
- 슬롯에는 모델 ID와 설정의 불변 적용본을 연결한다. 실행 중인 각 엔진은 생성 시 해당 적용본을 고정해서 읽는다. 모델 파일 자체는 읽기 전용 보관본을 재사용한다.
- 현재 홈/잠금 화면에서 사용하는 슬롯은 덮어쓰지 않는다. 시스템 미리보기만 열거나 취소해도 현재 적용본은 유지된다.
- API 34 이상은 시스템의 홈/잠금 컴포넌트를 각각 확인한다. 이전 API나 확인 실패 시 사용 중인지 불확실한 슬롯을 재사용하지 않는다. 안전한 빈 슬롯이 없으면 기존 배경을 보존하고 안내한다. minSdk 23은 유지한다.
- 모델 파일은 적용 후 앱 화면이 닫혀도 읽을 수 있어야 한다. 여러 엔진이 같은 전역 WebView를 공유하지 않는다.
- 홈/잠금 적용 대상은 시스템이 제공하는 선택 UI를 따른다. 앱은 잠금화면 해제·우회·강제 적용을 하지 않는다. 시스템에서 확인하지 못한 대상을 성공했다고 표시하지 않는다.

## 8. 생명주기, 오류 복구, 자원 사용

- 엔진별 WebView·Presentation·VirtualDisplay 소유권과 세대 번호를 유지한다. 오래된 비동기 콜백이 새 엔진을 정지시키지 않도록 검사한다.
- 숨김/화면 꺼짐에는 네이티브 가시성과 JS 정지를 함께 적용한다. 보이지 않는 상태의 `visibilitychange`가 렌더를 재시작하지 못하게 한다.
- Surface 소멸 시 예약 작업과 렌더 자원을 정리한다. 엔진 소유 Surface 자체를 임의로 release하지 않는다.
- 렌더러 종료, WebGL 컨텍스트 손실, 페이지/모델 로딩 실패를 분리해 감지한다. 로딩 허용 시간은 보이는 시간 누적으로 45초이며 숨겨진 시간은 제외한다.
- 유효한 Surface가 보이는 상태의 일시적 오류만 1초·3초 간격으로 최대 2회 재시도한다. 숨김/종료 중 재시도하지 않는다. 화면 꺼짐/복귀만으로 실패 횟수를 초기화하지 않으며, 30초 정상 렌더 또는 명시적 재시도/새 적용본으로 초기화한다. 손상 모델이나 반복 실패는 재시도를 멈추고 앱에서 `다시 시도` 또는 다른 모델 선택을 안내한다. 자동으로 다른 캐릭터·유료 서비스로 전환하지 않는다.
- 외부 URL, 임의 파일/content 접근, JS 네이티브 브리지 추가를 금지한다. 기존 로컬 리소스 허용 목록을 공유한다. INTERNET 권한을 추가하지 않는다.
- 화면 품질/프레임 제한은 기존 30fps 상한부터 측정한다. 실제 30fps를 보장한다고 홍보하지 않는다. 모델 전환 및 엔진 폐기 시 기하·재질·텍스처를 해제한다.

## 9. 검증 및 배포 기준

- 로컬 모델 A/B 모두 실제 SAF 가져오기 성공. 동일 파일명으로 공존하고 A → B → A 전환·재시작 후 목록 유지 확인.
- 두 버전의 정상/손상 파일, 외부 리소스, 텍스처 경계, 메타·뼈 구조, 중복 가져오기, 가져오기 실패 후 보존, v1.18 이전 경로에 자동화 검사 추가.
- 모델별 전신·얼굴·정면·눈 깜박임을 실제 화면으로 확인한다. 앱 미리보기와 홈 배경화면을 모두 캡처한다.
- 설정 변경 및 재실행 후 위치/크기 유지, 시스템 미리보기 취소 후 기존 모델 유지, 홈/잠금 엔진 동시 존재 시 적용본 분리 검사.
- 홈 ↔ Settings, 화면 꺼짐/복귀, 최근 앱에서 런처 제거, 태블릿 가로/세로 회전, 반복 모델 교체, 렌더러 종료/컨텍스트 손실 복구 검사.
- 앱 본체와 WebView 렌더 프로세스의 메모리를 함께 기록한다. GPU/시스템 메모리가 별도임을 명시하고 프레임·실패 여부를 보고한다.
- `testDebugUnitTest`, `lintDebug`, `assembleDebug`, 관련 instrumentation 및 웹 테스트를 실행한다. 빌드 성공만으로 모델 표시 성공을 대신하지 않는다.
- 기본 검증 기기는 로컬 API 36 휴대폰/태블릿 에뮬레이터다. 승인된 실기기 연결 시 Galaxy 테스트를 추가한다. 연결 불가 시 에뮬레이터 작업을 중단하지 않고 삼성 발열·전력·잠금화면 검증은 미확인으로 표시한다.
- 코드 변경 후 AST-only Graphify 업데이트. 기존 변경을 보존하고 본 작업 파일만 커밋한다.
- 배포 시 버전 `1.19`, versionCode `22`로 증가한다(중간에 새 배포가 있으면 그보다 큰 번호 사용). GitHub Actions 버전 검증·릴리스 파일명도 함께 갱신한다.
- GitHub Actions 성공 및 로컬 업데이트용 APK의 버전·서명·해시 확인 후 공개 Release 직접 다운로드 링크를 제공한다. 개인 VRM은 APK/소스/CI artifact에 절대 포함하지 않는다.

`ChargingAccessibilityService`, 기존 MagicWallpaperService의 Canvas 렌더 경로, 사용자의 Kotlin 드로잉 파일, Gradle·디버그 화면의 기존 사용자 수정사항은 이번 기능을 이유로 덮어쓰지 않는다.

## 검토 요청

사용자가 승인한 두 파일 지원 및 v1.19 기능을 이 설계대로 구체화했다. 다음 단계는 이 문서 검토 → 구현 계획 검토/실행 방식 선택 → 구현·검증·배포다. 현재 두 모델의 실행 성공이나 새 APK 배포를 완료했다고 주장하지 않는다.

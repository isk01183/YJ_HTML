# 별을 읽는 성역 — v1.12 네이티브 충전화면 설계

상태: 사용자 검토용 설계. 새 화면의 구현·빌드·GitHub 게시 완료 보고가 아닙니다.

## 1. 목표와 보존 범위

사용자가 제공한 864×1536 기준 이미지의 구도, 금빛·청백색 광량, 네 모서리 나선은하, 룬과 정돈된 기하 구조를 Kotlin 코드로 재현합니다. 이미지를 배경으로 깔거나 PNG/JPG/WebP로 마법진을 대신하지 않습니다. 구조를 맞추는 것과 원본 동등 화질 달성은 별도로 검수합니다.

- 새 도안 식별자: `N01`, 이름: `별을 읽는 성역`.
- 기존 118개 직접 그리기 도안, 기존 선택지, 업로드 자료, 숨김·복원, 세 언어 기능은 보존합니다. 기존 도안까지 Kotlin으로 다시 만드는 작업은 포함하지 않습니다.
- 새 설치의 기본 선택은 N01입니다. 업데이트 설치에서는 기존 사용자 선택을 임의로 덮어쓰지 않고 N01을 목록 맨 앞에 표시합니다. 사용자가 N01을 선택하면 미리보기와 실제 충전 모두 같은 네이티브 렌더러를 사용합니다.
- 충전 연결부터 최대 7초, 분리 시 즉시 종료, 재연결 시 새 실행을 유지합니다. 잠금 해제·우회, 배경화면 변경, 무기한 화면 켜기는 하지 않습니다.
- 인터넷 없이 작동하고 새 INTERNET 권한을 추가하지 않습니다.
- 추가 종량제 유료 서비스, 이미지 생성 API, 인증 설정 변경은 사용하지 않습니다.

## 2. 확인한 기존 상태

- 실제 앱은 Java 서비스와 WebView 기반이며 Kotlin 소스는 아직 없습니다. 새 렌더러는 Kotlin으로 작성하고 기존 서비스·미디어 관리는 필요한 접점만 수정합니다.
- 최신 v1.11 검수판은 `android-v1.11-work`에 있습니다. GitHub 작업 브랜치는 아직 v1.10 커밋 `7715ae8`입니다. v1.11 변경분을 먼저 비교·보존해서 기능이 되돌아가지 않도록 합니다.
- 원격: `https://github.com/isk01183/YJ_HTML.git`, 작업 브랜치: `codex/charging-overlay`. main 병합과 사용자 파일 삭제는 하지 않습니다.
- minSdk 23, compileSdk/targetSdk 37, Java 17, AGP 9.3.0, Gradle 9.5.0입니다. 새 배포 번호는 versionCode 15 / versionName 1.12를 제안하며, 실행 직전 더 높은 버전이 있으면 그보다 증가시킵니다.
- 현재 `app/src/test`가 없어 이전 Gradle 단위 테스트는 NO-SOURCE였습니다. 이번에는 실제 실행되는 단위 테스트를 추가합니다.
- 마지막 연결 확인 기기는 Galaxy S22(SM-S901N)입니다. S26 Ultra와 Tab S11 Ultra의 실기기 검증을 대신하지 않습니다.

## 4. 화면 배치와 시각 기준

원본을 눈으로 확인해 정한 초기 기준 좌표입니다. 정밀 측정 완료 수치가 아니며 렌더링 비교로 조정합니다.

864×1536 설계 좌표에서 중앙 마법진 중심은 약(432,718), 외곽 반지름은 약400~405, 중앙 코어 반지름은 약142입니다. 제목은 y≈190, 부제 y≈270, 하단 설명은 y≈1260, 정보 값은 y≈1360, 달 위상 장식은 y≈1460을 기준으로 합니다.

- 원을 타원으로 늘리지 않도록 균일 배율을 적용합니다. 태블릿·가로 화면에서는 전체 핵심 구도를 잘리지 않게 맞추고 남는 공간은 절차적 우주 배경으로 채웁니다.
- 상단 카메라 구멍·상태 표시줄·하단 내비게이션 영역에 중요한 글자가 가리지 않도록 안전 영역을 반영합니다.
- 상단 중앙의 큰 별, 금색 가로선과 점, 요청한 한국어 제목·문구를 유지합니다. 기존 언어 선택에 따라 대응 번역을 표시하며 한국어가 원본 비교 기준입니다.
- 배경: 검정/남청색, 네 코너의 비대칭 청색 나선은하, 황백색 중심, 파란 성운 덩어리, 가는 별자리 선, 작은 행성 2개. 단순 난수 점만으로 완료 처리하지 않습니다.
- 외곽: 3중 이상 밝은 금색 링, 약한 넓은 광막과 가는 고휘도 중심선, 4방향 큰 십자 플레어, 금색 룬48개, 대각선 초승달4개.
- 내부: 외곽 금색 밴드와 분리된 청백색 링, 작은 룬54개, 미세 눈금. 글꼴 누락을 막기 위해 룬을 선과 Path로 구성합니다.
- 기하: 닫힌 삼각형·6방/8방 도형, 방사선, 접점 노드. 겹치는 선의 수를 제한하고 꼭짓점은 동일 좌표를 공유합니다.
- 오비탈: 정지된 큰 타원4개, 실제 궤도 위의 청백색 노드8개. 코어 앞을 가로지르는 선은 코어 레이어 뒤에 둡니다.
- 코어: 검은 행성 질감과 청색 별먼지, cyan 광륜, 얇은 금색 테두리. 큰 배터리 숫자와 작은 %는 실제 글자 폭으로 함께 중앙 정렬합니다. 0/9/69/100 모두 겹치지 않아야 합니다.
- 하단: 요청 문구, 온도·건강·연결 방식의3열, 금색 구분선·별빛, 벡터 달 위상5개. 알 수 없는 수치는 예시 수치로 채우지 않습니다.
- 기준 이미지의 판독 불가능한 미세 룬과 생성 이미지 특유의 질감을 완전히 동일하다고 주장하지 않습니다. 남은 차이를 비교 화면과 함께 기록합니다.

## 5. 렌더링 구조와 성능

새 코드는 `com.yj.magiccircle` 패키지에 두어 기존 앱과 연결합니다.

| 파일 | 역할 |
|---|---|
| `MainMagicChargeView.kt` | 크기·안전 영역, 배터리 갱신, 표시/종료 수명주기, 전체 그리기 순서 |
| `CosmicBackgroundRenderer.kt` | 은하·성운·별·행성, AGSL 가능 여부와 Canvas 대체 경로 |
| `MagicCircleRenderer.kt` | 캐시한 링·룬·기하·궤도·중앙 코어 |
| `ChargeStatusPanelRenderer.kt` | 상하단 문구, 동적 배터리 텍스트, 접근성 설명용 텍스트 |
| `ChargeSnapshot.kt` | 검증된 배터리 값과 상태 변환, Android 그리기와 분리해 단위 테스트 |
| `SanctuaryLayout.kt` | 배치·배율·회전각 계산, 일반 JVM 단위 테스트 |

Compose 전체 전환보다 기존 View/WindowManager 서비스에 바로 붙는 Custom View를 채택합니다. 네이티브 그림을 WebView 안에서 다시 표시하지 않습니다.

AGSL은 API33 이상이면서 하드웨어 Canvas일 때만 사용합니다. API23에서도 로딩할 수 있도록 신규 API 참조를 별도 지원 경로 안에 가둡니다. 셰이더 생성/컴파일이 실패하면 로그를 남기고 Canvas 렌더러를 사용합니다. GPU 드라이버의 모든 실패를 예외 처리로 보장할 수 있다고 가정하지 않고 별도 Canvas 경로도 실제 검사합니다.

Canvas 대체 경로도 나선 팔의 연속 곡선, 밀도 차이, 성운 다중 그라데이션, 별무리, 밝은 중심을 갖춥니다. 사용자 이미지나 사전 렌더링 그림 파일에 의존하지 않습니다. BlurMaskFilter, LAYER_TYPE_SOFTWARE, 실험 API는 사용하지 않습니다.

Paint/Path/Shader/RectF/Typeface와 도형 좌표·별 위치는 초기화 또는 크기 변경 때 준비합니다. 문자열 포맷은 상태 변경 때만 합니다. onDraw 안에서 목록 생성·삼각함수로 전체 도형 재구축·셰이더 컴파일을 하지 않습니다.

## 6. 애니메이션과 충전 연결

- 금색 룬: 시계 방향 한 바퀴180초. 푸른 룬: 반시계 방향 한 바퀴240초. 시작 기준 시간을 매 재연결마다 초기화합니다.
- 기하·궤도·코어·초승달·프레임은 고정합니다. 배경 이동은 없고 소수 별만 약하게 반짝입니다.
- 시스템 애니메이션 비활성화 시 정적 화면을 유지합니다. 화면이 보이지 않거나 View가 분리되면 프레임 예약과 배터리 수신 등록을 해제합니다.
- `ChargingAccessibilityService`의 연결/분리 감지, 7초 종료 시각, 잠금 우회 금지, 재시작 시 이전 오버레이 제거는 유지합니다.
- N01 선택 시에만 네이티브 View를 생성합니다. 기존 도안과 업로드 파일은 기존 WebView 경로로 보존합니다. N01에는 PAGE_READY/JS_STARTED 대기와 JS 재시도를 적용하지 않습니다.
- 미리보기와 충전 오버레이가 같은 그림·상태 모델을 사용합니다. 접근성 오버레이는 기존처럼 터치와 포커스를 가로채지 않습니다.

## 7. 배터리 정보의 정확성

- 퍼센트: level/scale 범위 확인 후 계산. scale≤0, 누락·잘못된 값은 알 수 없음.
- 온도: EXTRA_TEMPERATURE의 섭씨10분의1 값을 변환. 실제0도와 누락을 구분합니다.
- 건강: EXTRA_HEALTH로 양호/과열/저온/기타/알 수 없음을 판단합니다.
- 충전 상태: EXTRA_STATUS로 충전 중/완충/충전하지 않음/방전 중을 구분합니다. 참고 코드의 status=4를 충전 완료로 표시하는 오류를 수정합니다.
- 연결 방식: EXTRA_PLUGGED로 AC/USB/무선/기타/미연결을 판단합니다. USB 연결을 고속 충전으로 추정하지 않습니다.
- 앱의 실제 표시와 원본 비교용 테스트 데이터(69%,32.5°C)는 분리합니다. 사용자 화면에서 테스트 값으로 실제 값을 덮어쓰지 않습니다.

## 8. 빌드·배포·검증 기준

1. 기존 v1.11과 Git 브랜치의 차이를 비교해 최신 기능·원본 자료를 보존합니다. 별도 작업 공간에서 변경하고 main에는 병합하지 않습니다.
2. AGP의 Kotlin 지원과 현재 툴체인 호환성을 공식 문서 및 실제 빌드로 확인합니다. 중복 Kotlin 플러그인이나 불필요한 UI 라이브러리를 추가하지 않습니다.
3. 배치·회전 방향·정지 레이어·배터리 변환·반복 연결/종료에 실패하는 테스트를 먼저 만들고 구현 후 통과시킵니다.
4. `testDebugUnitTest`, `lintDebug`, `assembleDebug`를 실행합니다. NO-SOURCE를 단위 테스트 통과로 보고하지 않습니다.
5. 실제 Android 화면에서 한국어 고정 테스트 상태를 캡처해 원본과 나란히 비교합니다. 원 지름/코어 비율, 문구 위치, 은하 밀도, 광량, 룬 가독성, 접점, 100% 숫자 폭을 확인합니다.
6. API23 대체 경로와 API33 이상 AGSL 경로, 강제 Canvas 경로를 검사합니다. 실기기 없이 검증하지 못한 항목은 미확인으로 남깁니다.
7. 연결 가능한 기기에서 시작·종료·10회 재연결·화면 꺼짐/켜짐·회전과 앱 오류 로그를 확인합니다. 실제 케이블 검증과 모의 이벤트 검증을 구분합니다.
8. GPU/프레임·메모리 결과는 기기와 측정 조건을 함께 기록합니다. S22 측정을 S26/Tab S11 수치로 보고하지 않습니다.
9. GitHub Actions에 JDK·SDK 설치, Gradle Wrapper 검증, 테스트/lint/debug 빌드, APK와 검사 보고서 artifact 업로드를 구성합니다. 결제 가능한 runner와 유료 서비스를 사용하지 않습니다. 저장소 공개 여부·무료 실행 조건을 확인할 수 없으면 실행 전에 멈추고 알립니다.
10. 실행한 커밋과 Actions 성공 상태, APK artifact 다운로드 링크·SHA-256을 함께 보고합니다. 워크플로 파일 작성만으로 원격 빌드 성공이라 하지 않습니다. GitHub artifact APK는 CI debug 서명이 기존 로컬 설치와 다를 수 있으므로, 업데이트 호환성은 별도로 확인하고 앱 삭제나 서명키 공개를 하지 않습니다.

## 9. 비교 결과 보고 형식

완료 시 구현된 Kotlin 전체 소스와 변경 파일 목록, 커밋 링크, Actions 실행 링크, APK artifact, 실제 Android 캡처를 제공합니다. 원본과의 비교는 배치·기하·은하·광원·문자별로 맞춘 점과 남은 차이를 구분합니다. 근거 없는 일치율이나 완벽 재현 주장은 하지 않습니다.

## 10. 설계 검토 및 다음 단계

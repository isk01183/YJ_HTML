# v1.15 화면 만들기·충전 정보 편집 설계

상태: **2026-10-07 사용자 승인 / 실행 계획 작성 단계**. 문서 검토 요청 후 사용자가 “진행해”로 다음 단계를 승인했습니다. 제품 코드 구현·새 APK 빌드는 아직 하지 않았습니다.

## 1. 확정한 목표

첫 화면에서 여러 이미지를 겹쳐 나만의 배경화면·잠금화면·충전화면을 만듭니다. 저장 후 다시 편집할 수 있어야 합니다. 충전 정보 위치와 표시 여부 편집은 직접 만든 화면뿐 아니라 **기존 마법진 전체**에도 적용합니다.

- 이미지: JPG/JPEG, PNG, GIF. 레이어별 위치·크기·각도·좌우 반전·앞뒤 순서·표시/숨김·제거.
- 충전 정보: 배터리 %, 충전 상태, 온도, 배터리 상태, 연결 방식 등 앱이 표시하는 모든 충전 관련 정보.
- 표시 시간: **1초 / 3초 / 5초 / 7초**, 기본 7초. 모든 충전 디자인에 공통 적용하고 재실행 후에도 유지.
- 연결 해제 시 즉시 종료, 재연결 시 첫 장면부터 새 실행. 인터넷 없이 작동하고 잠금을 해제하지 않음.
- 기존 마법진 그림, 사용자 이미지, 사용자 탭, 활성/비활성 상태 및 선택을 보존.
- 한국어·일본어·영어와 minSdk 23 유지. 유료 API·외부 서비스·새 계정 연결 없음.

기준 작업 폴더는 `stellar-sanctuary-v112/MagicCircleAndroid`, 브랜치는 `codex/stellar-sanctuary-v112`입니다. 현재 작업 폴더는 v1.14 / versionCode 17이며 미커밋 변경이 있습니다. 다음 배포는 **v1.15 / versionCode 18**을 예정하되 실제 배포 직전 최신 번호와 서명을 다시 확인합니다. 이번 문서 커밋에는 기존 미커밋 제품 파일을 포함하지 않습니다.

## 2. 구현 방식 비교와 선택안

| 방식 | 장단점 | 결정 |
|---|---|---|
| 기존 목록 화면 + 네이티브 레이어 편집기 + 공통 Canvas 합성 | 기존 업로드·배경화면 기능 재사용. 편집 미리보기와 실제 합성을 같은 코드로 검증 가능 | 추천 |
| HTML 편집기와 네이티브 배경화면 합성을 각각 구현 | 기존 웹 화면과 자연스럽지만 변환·GIF·글자 배치를 두 번 구현해야 함 | 제외 |
| 완성 화면을 이미지 한 장으로 저장 | 단순하지만 GIF 재생·실시간 배터리·레이어 재편집을 잃음 | 제외 |

기존 마법진 렌더러를 전부 새로 만들지 않습니다. 마법진은 기존 방식으로 그리고, 사용자가 편집한 충전 정보만 공통 정보 레이어로 분리합니다. 새 외부 편집기 라이브러리나 데이터베이스는 추가하지 않습니다.

## 3. 사용자 화면 흐름

### 첫 화면과 작품 목록

기존 `배경화면/잠금화면`, `충전 애니메이션 변경` 버튼을 유지하고 **`화면 직접 만들기`**를 추가합니다. 들어가면 `배경화면·잠금화면용`과 `충전화면용` 중 용도를 선택합니다.

- 이미지 보관함에서 불러오거나 시스템 파일 선택기로 새 파일을 가져옵니다. 한 번에 한 장씩 추가해도 여러 레이어를 만들 수 있습니다.
- 작품 이름을 정해 저장하면 해당 용도의 기존 선택 목록에 함께 나타납니다. 안정적인 내부 ID는 이름을 바꿔도 바뀌지 않습니다.
- 저장·미리보기·편집만으로 현재 충전 선택이나 시스템 배경화면을 바꾸지 않습니다. 별도 `적용`을 눌러 변경합니다.
- 기존 마법진과 단일 업로드의 상세 영역에는 `충전 정보 편집`을 둡니다. 비활성 도안도 관리 화면에서 편집할 수 있지만 편집이 도안을 자동 활성화하지 않습니다.
- 작품 삭제와 레이어 제거는 구분합니다. 레이어 제거는 구성만 바꾸며 휴대전화 원본 파일을 삭제하지 않습니다.

### 편집기

위쪽은 실제 출력 비율의 미리보기, 아래쪽은 레이어 목록과 선택 항목의 조절부입니다. 작은 화면에서는 조절부를 스크롤하며, 태블릿에서는 미리보기와 조절부를 나란히 배치할 수 있습니다.

- 화면에서 드래그해 이동. 확대/축소 제스처와 크기 조절부를 함께 제공.
- 각도 조절부 및 숫자 입력, `좌우 반전`, `앞으로/뒤로`, `표시/숨김`, `레이어 제거` 제공.
- 이미지 원래 가로세로 비율은 유지합니다. 회전·반전 중심은 레이어 중앙이며 투명 PNG는 아래 레이어가 보입니다.
- 선택 테두리와 조절 손잡이는 편집기에서만 보이며 실제 충전·배경화면에는 나오지 않습니다.
- 레이어 전체가 화면 밖으로 사라지지 않도록 최소 일부가 보이게 제한하고 `가운데로`로 복구합니다.
- `저장`, `미리보기`, `취소`를 구분. 변경 후 뒤로 가기는 저장/버리기/계속 편집 중 선택.
- 화면 회전·프로세스 재생성 때 복구 가능한 임시 초안을 보존하되 저장 작품·적용 중 배경화면은 건드리지 않습니다.
- 글자로 된 버튼 설명, 선택 상태, 48dp 이상 조작 영역 및 스크린리더 설명을 제공합니다. 제스처만으로 가능한 필수 기능은 두지 않습니다.

## 4. 모든 마법진의 충전 정보 편집

설정은 **디자인별**로 저장합니다. N01의 배터리 위치를 옮겨도 W03이나 다른 작품의 위치를 바꾸지 않습니다. 표시 시간만 앱 전체 공통입니다.

| 편집 항목 | 표시 내용 / 규칙 |
|---|---|
| 배터리 잔량 | 숫자와 %를 한 묶음으로 이동·표시/숨김 |
| 충전 상태 | 충전 중·충전 대기·완료·미연결·알 수 없음 등 실제 상태 |
| 배터리 온도 | 값과 항목 이름을 한 묶음으로 이동·표시/숨김 |
| 배터리 상태 | 양호·과열·저온·알 수 없음 등 실제 보고값 |
| 연결 방식 | AC·USB·무선·도크·미연결 등 실제 보고값 |
| 잔량 표시 막대/아이콘 | 기존 화면의 배터리 막대·아이콘도 따로 켜거나 끄고 이동 |
| 연결/시작/완료 안내 | 기존 단계별 충전 안내 문구를 하나의 메시지 영역으로 묶어 이동·표시/숨김. 문구 변화와 단계 순서는 유지 |

각 항목을 독립적으로 선택해 이동하고 켜거나 끕니다. 짧은 글자·긴 번역·글꼴 확대에서도 안전 영역 안에 표시하며 충전 정보가 잘리지 않도록 배치를 제한합니다. 원래 없던 항목은 기본적으로 꺼져 있지만 편집기에서 켤 수 있습니다. 새 충전 작품은 잔량·충전 상태만 기본 표시합니다.

**호환성 규칙:** 정보 편집을 저장하지 않은 기존 디자인은 기존 배치·서체·장식 그대로 표시합니다. 편집 저장 후에는 원래 화면의 해당 동적 정보만 숨기고 공통 정보 레이어에서 한 번만 표시합니다. 원래 배경의 빈 코어·테두리는 제거하지 않습니다. `기본 배치로 복원`하면 사용자 지정 설정을 제거하고 원래 배치로 돌아갑니다.

N01의 중앙 정보, W03/R01의 하단 배지, HTML 테마의 중앙/하단 중복 잔량, 메트릭, 막대, classic의 단계별 안내를 모두 포함합니다. 제목·룬 문자·축복 문구처럼 **그림의 정적인 장식 문구**는 충전 데이터가 아니므로 이번 위치 편집 대상에서 제외합니다. 업로드 이미지 픽셀 안에 이미 그려진 글자는 분리할 수 없으며, 앱이 덧붙인 정보만 편집합니다.

화면에 표시할 값은 기존 `ChargeSnapshot`과 실제 배터리 이벤트에서 얻습니다. 편집기는 실측값을 쓰고, 값을 얻지 못하면 `—` 또는 `알 수 없음`으로 표시합니다. 고속 충전·완충 예상 시간·배터리 수명 같은 미확인 수치를 만들어 표시하지 않습니다. 실제 배터리 상태와 연출용 연결/완료 문구는 구분합니다. 공통 정보가 켜진 실행은 하나의 수신 경로로 갱신하고 중복 수신기를 만들지 않으며, 숨긴 항목은 접근성 설명에서도 제외합니다.

## 5. 1·3·5·7초의 정확한 의미

충전 선택 화면과 충전 편집 미리보기에서 같은 **공통 표시 시간** 버튼을 사용합니다. 버튼은 현재 선택 상태를 명확히 보여주며 한 번에 하나만 선택합니다. 잘못된 저장값은 7초로 복구합니다.

- **표시 시간은 콘텐츠 준비 후 재생을 시작한 순간부터 계산**합니다. 1초를 선택했는데 로딩만 하다가 끝나지 않도록 합니다.
- 연결부터 준비까지는 별도 최대 2초의 시작 제한을 둡니다. 준비 중에는 기존 화면을 가리지 않으며 실패하면 표시를 포기하고 정리합니다. 따라서 연결부터 정리까지는 준비 시간 + 선택 시간이고, 실제 연출이 보이는 시간은 최대 7초입니다. 이는 현재 연결 즉시 7초를 세는 코드와 달라지는 점입니다.
- 네이티브 첫 그리기 준비와 웹 자산 준비/JS 시작 확인을 구분합니다. **JS 시작을 `postVisualStateCallback` 대기 조건으로 바꾸지 않습니다.** 화면 렌더링 확인이 늦어도 교착되거나 검은 화면으로 고정되면 안 됩니다.
- 준비 함수가 로딩 완료와 동시에 몰래 재생을 시작하지 않도록 준비/시작 계약을 분리합니다. 네이티브가 정한 시작/종료 기한을 재생 요청에 함께 전달하고, 요청 전달 지연은 남은 예산에서 뺍니다. 다음 250ms 재시도의 성공 응답을 시작 시각으로 삼아 표시 시간이 늘어나는 기존 웹 경로의 함정을 제거합니다. 화면 그리기 지연은 검사 로그에 따로 기록하며 밀리초 단위의 물리적 화면 표시 정밀도를 약속하지 않습니다.
- 표시 시작·종료 기한은 네이티브 세션 하나가 소유합니다. 웹 페이지나 GIF가 종료 시간을 연장하지 못합니다. 준비 제한과 종료 타이머에도 실행 ID를 붙여 이전 실행의 콜백이 새 실행을 종료하지 못하게 합니다.
- 앱의 등장/단계/퇴장 연출만 선택 시간에 맞춥니다. 외곽 룬의 원래 느린 회전, 정지 도형, GIF 원본 재생 속도는 빨라지지 않습니다. GIF는 매 연결마다 첫 프레임부터 재생하고 시간이 끝나면 종료합니다.
- 도중 시간 설정을 바꿔도 진행 중인 실행은 시작 당시 값을 사용하고 다음 실행부터 새 값을 사용합니다.
- 분리, 화면 꺼짐, 서비스 종료, 실패 시 타이머·그리기·GIF·WebView를 정리합니다. 재연결은 새 실행이며 항상 처음부터 시작합니다.
- 편집 화면의 정적 배치는 시간 제한이 없고, `충전 미리보기`에만 선택 시간을 적용합니다. 라이브 배경화면에는 1·3·5·7초 제한을 적용하지 않습니다.

## 6. 공통 좌표와 렌더링

새 작품은 검은 바탕 위에 아래 레이어부터 차례로 합성합니다. 이미지 파일을 매 프레임 다시 읽지 않고 준비 시 크기에 맞춰 디코딩합니다.

- 이미지 중심 x/y는 화면 너비/높이의 0~1 비율, 이미지 너비는 화면 짧은 변의 0.05~4배, 각도는 -180도 이상 180도 미만, 좌우 반전은 불리언으로 저장합니다. 이미지 높이는 원본 비율로 계산합니다. 정보 중심도 안전 영역의 0~1 비율로 저장하고 실제 글자 경계를 안쪽으로 보정합니다. 저장값은 유한수·허용 범위인지 검사합니다.
- 배경 레이어는 전체 화면에 그리되 정보 레이어는 시스템 표시줄·카메라 구멍을 피한 안전 영역에 배치합니다. 편집기에 해당 경계를 표시합니다.
- 다른 화면 비율에서는 중앙 기준 비율 배치를 유지하며 필요 시 여백을 허용합니다. 미리보기에서 적용 대상 비율을 확인하고, 태블릿 회전 시에도 손실 없이 복원합니다.
- 동일한 합성 코드와 변환 순서를 편집 미리보기·충전 작품·정지 배경화면 출력·라이브 배경화면에서 사용합니다. 저장할 때 전체 화면을 한 장의 이미지로 굳히지 않습니다.
- 정지 배경화면 적용 때만 시스템에 전달할 비트맵을 만들고 GIF는 첫 프레임을 사용한다고 안내합니다. 라이브 배경화면에서는 GIF를 원래 속도로 반복합니다.
- 마법진 자체는 기존 네이티브 또는 WebView 렌더러를 유지하고 공통 충전 정보 View만 위에 겹칩니다. 편집하지 않은 디자인의 기존 정보 경로는 유지합니다. 창에 붙는 루트 컨테이너와 내부 렌더러 참조를 분리하고, 기존 `overlay instanceof WebView` 분기·실행 ID 검사·종료 시 자원 해제를 모두 함께 수정합니다. `.readout`이나 N01 패널 전체를 숨기지 않고 데이터 항목만 분리해 장식·작품 코드가 사라지지 않게 합니다.
- `Paint`, `Path`, `Matrix`, 출력 버퍼를 재사용하고 프레임 중 파일 I/O와 불필요한 객체 생성을 하지 않습니다. 정지 화면은 변경 시만, GIF 합성은 최대 30fps로 그립니다. 숨겨진 레이어·꺼진 화면은 재생하지 않습니다.

### 초기 안전 범위

작품당 이미지 레이어 **최대 8개**, 그중 GIF 레이어는 숨김 여부와 관계없이 **최대 2개**를 초기 범위로 제안합니다. 한도를 넘기면 원인을 안내하고 기존 작품을 보존합니다. 숨긴 GIF는 디코딩·재생 대상에서 제외합니다.

기존 파일별 20MiB·형식·해상도·GIF 프레임 수 검사를 유지합니다. 합성 디코딩 캐시는 기기 메모리 등급의 1/4과 48MiB 중 작은 값 이내로 관리하고, 프레임 버퍼·동시 디코더도 함께 예산에 넣습니다. 크기에 맞춘 샘플링으로 한도를 지키며, 부족하면 오류를 알리고 이전 저장/적용 상태를 유지합니다. 이 수치는 무한 레이어를 약속하지 않기 위한 초기 상한이며 에뮬레이터에서 최대 구성까지 검증합니다.

## 7. 저장·삭제·업데이트 안전성

기존 `MediaLibrary`의 원자적 JSON 저장을 확장해 작품과 정보 배치를 함께 관리합니다. 별도 데이터베이스·클라우드를 만들지 않습니다.

- 스키마 v2를 v3로 이전하기 전에 v2 원본의 전용 복구본을 보존합니다. 기존 v1→v2 경로와 이미 있는 복구본을 삭제하거나 재사용해 덮지 않습니다.
- 기존 필드(선택, 탭, 미디어, 숨김 상태)에 작품 목록, 디자인별 정보 배치, 공통 표시 시간을 추가합니다. 파일 크기 상한을 유지하고 저장 전 완성 상태를 검증합니다.
- 작품은 `scene-<UUID>`처럼 이미지 UUID와 다른 ID 공간을 씁니다. `MediaValidation.isId()`의 파일 경로 검증을 느슨하게 바꾸지 않습니다.
- 작품 데이터에는 이름·용도·레이어 순서·참조 미디어 ID·좌표·크기·각도·반전·표시 상태와 충전 정보 배치를 저장합니다. 이름은 앞뒤 공백 제거 후 1~40자로 제한하며 제어문자를 거부하고 일반 글자로만 표시합니다. 경로나 실행 스크립트를 외부 입력에서 받지 않습니다.
- 시스템 파일 선택기로 받은 자료는 검증된 앱 전용 사본으로 가져옵니다. 레이어 추가용 가져오기는 현재 충전 선택을 바꾸지 않습니다.
- 작품·저장 초안에서 사용 중인 미디어의 보관함 삭제는 막고 사용 중인 작품을 안내합니다. 사용자가 레이어를 빼고 저장한 뒤 삭제할 수 있습니다. 잘못된 참조 상태에서는 자동 삭제하지 않습니다.
- 삭제 작업은 먼저 구성 저장을 확정한 뒤 참조가 없는 앱 사본만 정리합니다. 실패·커밋 결과 불명 시 추가 파괴 작업을 중지하고 원본과 복구본을 남깁니다. 휴대전화의 원본 파일은 건드리지 않습니다.
- 실행 중 충전 화면도 실행 시작 시 선택·설정·필요 자산의 고정 스냅샷/열린 자원 수명을 확보합니다. 보관함 삭제나 편집이 현재 실행을 중간에 깨지 않도록 보호합니다.
- 적용 중인 라이브 배경화면은 작품 설정과 모든 이미지의 **독립 사본**을 사용합니다. 후속 작품 편집·보관함 삭제가 이미 적용된 배경화면에 즉시 영향을 주지 않습니다.
- 기존 3개 업로드 배경화면 슬롯 정책을 확장하되 사용 중인 슬롯은 덮어쓰지 않습니다. 새 세대의 사본 전체를 만든 뒤 원자적 진입 문서로 확정합니다. 취소·오류·적용 여부 불명 시 현재 배경화면을 보존하며 기존 단일 파일 슬롯도 계속 읽을 수 있어야 합니다.
- 알 수 없는 문서 버전·손상된 참조·공간 부족은 사용자에게 안내합니다. 빈 보관함으로 초기화하거나 조용히 원본을 지우는 복구는 하지 않습니다.

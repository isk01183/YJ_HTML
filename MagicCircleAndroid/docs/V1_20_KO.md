# v1.20 — VRM 캐릭터와 이미지로 만드는 배경화면

버전 1.20 / versionCode 23. 기존 최소 SDK 23 유지. 개인 VRM과 이미지는 APK·Git·CI에 포함하지 않는다.

## 최종 목표와 이번 범위

목표는 **모바일 캐릭터 제작 → 원본 편집 정보와 버전별 캐릭터 보관 → 배경화면 편집에서 호출 → 이미지와 합성 → 라이브 배경화면 적용**이다.
이번 버전은 이 흐름 중 **기존 VRM 0.x/1.0 보관함을 배경화면 편집기에 연결**한다. 머리·얼굴·체형·의상을 VRoid처럼 만드는 고품질 3D 제작기를 완성한 버전은 아니다.
향후 제작기 출력도 같은 검증·보관 경로로 등록할 수 있게, 원본 캐릭터와 작품별 위치·크기 및 적용본을 분리했다. 외형 편집 데이터를 화면 좌표에 섞거나 원본 VRM을 덮어쓰지 않는다.

## 사용 방법

1. 첫 화면의 **화면 직접 만들기**에서 **배경화면**을 만든다.
2. 편집기의 **캐릭터 선택** → **VRM · 가져온 3D 캐릭터**에서 모델을 고른다. 목록의 이름·VRM 형식·짧은 ID로 같은 파일명도 구별한다. 아직 없다면 **VRM 가져오기 / 관리**를 이용한다.
3. JPG/PNG/GIF 이미지를 추가하고 캐릭터의 앞·뒤 겹침 순서를 조정한다. 캐릭터는 이동·크기·표시·눈 깜박임을 조정하고, 이미지는 기존 회전·반전 편집을 유지한다.
4. 저장 후 작품 목록에서 **미리보기** 또는 배경화면 적용을 연다. VRM 작품은 캐릭터를 빠뜨린 정지 이미지로 바꾸지 않고 라이브 배경화면으로 적용한다.
5. 실제 렌더링 준비가 끝나면 **시스템에서 적용**을 누르고 Android 시스템 화면에서 확정한다. 홈/잠금 선택 가능 여부는 OS·제조사 정책을 따른다.

한 작품에는 캐릭터 1명, 이미지 최대 8개(그중 GIF 최대 2개)를 사용한다. 2.5D 캐릭터와 VRM은 동시에 선택하지 않는다. VRM의 화면 이동 범위는 가로/세로 15–85%, 크기는 50–150%다. VRM 회전·춤·걷기는 이번 범위가 아니다.

## 저장과 복구

- 선택 자체는 단독 VRM 화면의 모델 선택·배치를 변경하지 않는다. 작품별 배치를 저장한다.
- 실제 첫 프레임 전에는 적용 버튼을 잠근다. 숨긴 캐릭터도 보관 파일의 SHA-256을 확인해 잘린 모델을 정상으로 취급하지 않는다.
- 적용 시 이미지와 배치를 별도로 복사하고, 준비 완료 후 원자적으로 발행한다. 원본 작품을 편집·삭제해도 현재 적용본은 유지된다. 기존 단독 VRM 적용본도 읽는다.
- 홈/잠금에 사용 중인 슬롯은 덮어쓰지 않는다. 준비/시스템 미리보기 중 다른 요청을 막고 오래된 결과는 새 요청을 해제하지 못한다.
- 중단 후 **이전 적용 계속**을 누르면 같은 준비본으로 시스템 미리보기를 다시 연다. 준비 전에 중단된 요청은 명시적으로 정리할 수 있다. 읽을 수 없는 손상된 예약은 안전을 위해 자동 삭제하지 않는다.
- API 34 미만 등 잠금 슬롯 사용 여부를 확신할 수 없으면 이미 발행한 슬롯을 보호한다. 안전한 슬롯이 없으면 적용을 중단한다. 기존 화면을 지우거나 강제 재사용하지 않는다.
- 화면이 가려지면 VRM/GIF 갱신을 멈춘다. 그래픽 오류는 최대 2회 자동 재시도 후 안내하며 수동 재시도가 가능하다.

## 구현 위치

- `ScreenScene.kt` / `VrmPlacement.kt`: 이전 작품과 호환되는 선택적 VRM 레이어와 위치 규칙.
- `VrmSceneView.kt` / `LayeredSceneRenderer.kt` / `VrmWebView.kt` / `vrm-viewer/`: 네이티브 뒷이미지 → 투명 3D WebView → 네이티브 앞이미지 합성. 중복 이미지/GIF는 하나의 캐시로 디코딩한다.
- `ScreenEditorActivity.kt` / `ScreenEditorView.kt` / gallery 자산: 선택·교체·편집·저장·전체 미리보기·목록 연결.
- `VrmSceneDialog.kt` / `WallpaperController.kt`: 공용 미리보기, 준비 확인, 시스템 적용과 중단 복구.
- `VrmWallpaperStore.kt` / `VrmWallpaperService.kt`: 별도 적용본, 요청/실행 토큰, 엔진별 자원·오류 복구. AtomicFile 읽기와 발행에 같은 짧은 잠금을 사용한다.

### 성능 표본

두 에뮬레이터 동시 실행/소프트웨어 GPU에서 관측한 값이며 순간 최대·GPU 전체 메모리가 아니다.

| 모델/에뮬레이터 | 앱 PSS 표본 | WebView PSS 표본 | 표시 중 관측 속도 |
|---|---:|---:|---:|
| VRM1 / 전화 1440×3120 | 약 119–121 MiB, 전환 후 약 109 MiB | 약 218 MiB | 약 4–9 fps |
| VRM0 / 태블릿 2560×1600 | 약 116–117 MiB, 전환 후 약 107 MiB | 약 273 MiB | 약 4–14 fps |

30fps는 상한이며 달성 보장이 아니다. 두 장시간 검사에서 OOM·지속적인 렌더 실패는 관찰되지 않았지만 장기 누수·실기기 전력을 증명하지 않는다.
초기 검사에서 테스트 종료가 앱 서비스를 강제 종료하는 점, 닫힌 시스템 미리보기와 실제 홈 렌더러를 혼동한 점, 설정 앱의 실제 전환보다 빨랐던 검사 시점을 수정했다. 이를 제품 오류 복구 성공으로 계산하지 않고, 수정된 검사로 실제 적용·가시성·복구를 다시 확인했다.

## 배포 원칙과 남은 검증

작업 폴더의 사용자 Gradle/직접 그리기 수정은 커밋하지 않는다. 배포용 로컬 APK는 커밋된 소스를 별도 폴더에 내보내 다시 빌드·검사하며, 기존 앱과 같은 로컬 디버그 인증서로 서명한다. CI APK는 서명이 다를 수 있으므로 기존 설치를 갱신할 때는 `local-update.apk`를 사용한다.
GitHub Actions 성공 및 공개 APK 재다운로드 해시 확인은 해당 릴리스 링크와 함께 별도로 보고한다. main 브랜치는 병합하지 않는다.

실제 S26 Ultra/Tab S11 Ultra 성능·발열·전력과 삼성 잠금화면 정책, 모든 OS 버전, 복사 중 전원 단절의 모든 타이밍은 확인하지 않았다. 준비 중단·파일 손상·동시 요청은 자동화된 실패/보존 검사로 별도 확인했다.

개인 캐릭터는 오프라인 로컬 보관이며 INTERNET 권한, 유료 API, 종량제 fallback을 추가하지 않았다. 기존 충전 감지, 마법진, 사용자의 Kotlin 드로잉·Gradle 변경은 이번 커밋에서 수정하지 않는다.
